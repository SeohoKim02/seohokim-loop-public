# Security policy

## Report privately

Use **Security → Advisories → Report a vulnerability** in [SeohoKim Loop](https://github.com/SeohoKim02/seohokim-loop-public/security/advisories), or open the [private reporting form](https://github.com/SeohoKim02/seohokim-loop-public/security/advisories/new).
GitHub requires you to sign in. If the private-report button is unavailable, do not substitute a public issue containing vulnerability details.
No personal email address is offered as a reporting channel.

Include the affected version or commit, expected security boundary, and a minimal reproduction with fictional data. Send only the smallest redacted evidence needed.
Never disclose API keys, authentication files, account details, personal history or sensitive attachments in public issues or discussions.
If a real credential was exposed, revoke or rotate it with its provider; deleting the latest file does not remove Git history.

## Support scope

This is an early source preview. There is no stable release, response SLA, bounty or guaranteed support period.
Reports about provider isolation, protected local storage, attachments, cancellation and dependency security are welcome.
Do not make paid AI requests, access someone else's data or run destructive tests to demonstrate an issue.

## Maintainer procedure

In repository **Settings → Security and quality → Advanced Security**, enable **Private vulnerability reporting** and verify its status and report link before announcing the repository. Do not submit a fake vulnerability to test reporting.
Review repository security notifications and access. Security fixes require relevant tests before release.
See [GitHub's setup instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository).
